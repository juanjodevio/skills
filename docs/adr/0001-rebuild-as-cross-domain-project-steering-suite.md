# Rebuild as a cross-domain Project steering suite

Rebuild the suite from scratch around one deep `steer-project` workflow and thin truth adapters for Intent, technology, design, roadmap, structure, decisions, and agent guidance. Project steering must work across software development, data engineering, and marketing through composable evidence adapters and configured artifact paths rather than domain-specific skill families.

Reuse compatible Matt Pocock skills for setup prerequisites, grilling with domain modeling, specifications, Tickets, implementation, retrospectives, and situational workflows. Do not vendor or reimplement those skills, and do not depend on Superpowers. Work tracking remains adapter-driven across Linear, GitHub, GitLab, Jira, local Markdown, and configured alternatives.

## Consequences

- Install the Project steering suite as a whole; focused installation is unsupported.
- Remove the old `product-steering` and abbreviated `steer-*` interfaces without compatibility aliases.
- Keep Specifications and Tickets canonical in the configured work tracker.
- Verify suite packaging through deterministic inventory checks (module list, frontmatter, references, obsolete-name absence). Skill behavior quality follows Matt’s skills-pack approach: editorial review and use in real Projects, not a committed scenario catalog.
